# MessMate – Student Food Feedback & Recommendation

## Personal Product Management Project

MessMate is a product idea for students to give feedback on their daily mess food and get useful food-related insights.

I came up with this idea by looking at how students give feedback about mess food and how different meals can receive different responses from students.

## Problem

In my college, students regularly give ratings for their mess food. A mess can serve around 500 students, while some larger hostels have more than 1,000 students eating in the mess.

I noticed that students can have very different opinions about different meals. For example, lunch may be less preferred compared to breakfast or dinner.

This made me think about how mess feedback can be collected and analysed in a more structured way.

Instead of only looking at an overall monthly rating, the feedback can be analysed based on:

- Different meals
- Breakfast, lunch and dinner
- Different hostels
- Student preferences
- Repeated complaints
- Meal-wise ratings

## Product Idea

The basic idea is to let students:

**See Today's Menu → Rate Meal → Give Feedback → View Insights**

For example:

**Rajma → 4/5 → Good taste → Would eat again**

The collected feedback can then be analysed to understand which meals students like, which meals have problems and where improvements may be needed.

## Main Features

Some features I considered are:

- Daily meal rating
- Written feedback
- Breakfast/lunch/dinner rating
- Favourite dishes
- Weekly food rating summary
- Feedback history
- Meal recommendations
- Mess feedback dashboard

## User Flow

The basic user flow is:

**Student → Today's Menu → Rate Meal → Give Feedback → Recommendations / Insights**

## Example Analysis

Suppose a meal receives lower ratings than other meals.

Instead of only knowing that the rating is low, the product can look at the feedback and identify possible reasons such as:

- Taste
- Food quality
- Menu repetition
- Variety
- Meal timing

This can help turn student feedback into useful product insights.

## Feature Prioritization

Since all features cannot be developed at the same time, I would compare them based on:

- User value
- Expected impact
- Number of students affected
- Development effort
- Operational value

This would help decide which features should be built first.

## MVP

For the first version, I would keep the product simple.

The MVP would include:

1. Today's menu
2. Meal rating
3. Written feedback
4. Basic feedback summary

Features like personalized recommendations and advanced dashboards can be added later.

## Product Metrics

Some metrics I would track are:

- Number of students giving feedback
- Feedback participation rate
- Average meal rating
- Meal-wise rating
- Repeat usage
- Most liked meals
- Most reported problems

## Possible A/B Test

One experiment could be to test whether showing students a simple weekly food summary increases feedback participation.

**Control Group:** Students see the normal feedback option.

**Treatment Group:** Students see a weekly summary of their ratings and food preferences.

The main metric could be:

**Feedback Participation Rate**

The result can be compared between the two groups before deciding whether the feature should be expanded.

## What I Learned

Through this project, I worked on:

- Identifying a user problem
- User journey
- Feature prioritization
- MVP planning
- Product metrics
- Feedback analysis
- A/B testing
- Product decision making

The main thing I learned is that collecting feedback is not enough. The feedback should be analysed to understand the actual user problem and decide what can be improved.
